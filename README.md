# sonarqube-coverage-scanner

CLI-утилита: отчёт по покрытию кода тестами (New Code и Overall) из SonarQube Community Build v24.12 с установленным [Community Branch Plugin](https://github.com/mc1arke/sonarqube-community-branch-plugin).

Утилита читает список проектов из `projects.json`, для каждого определяет ветку (из конфига или автоматически — последнюю релизную), запрашивает метрики покрытия через Web API SonarQube и сохраняет сводку в CSV-отчёт в папке `OUTPUT_FOLDER` (по умолчанию `reports`).

## Требования

- Python 3.11+
- Доступ к SonarQube по HTTP(S) и пользовательский токен (`squ_…`) с правом **Browse** на проекты из `projects.json`
- Python-зависимости: `httpx`, `python-dotenv` (см. `requirements.txt`)

## Установка

```bash
cd C:\_NSD\Tools\sonarqube_coverage_scanner
python -m venv .venv
. .venv/scripts/activate
pip install -r requirements.txt
```

## Настройка

Скопируйте `.env.example` в `.env`. Заполните значения в `.env` и `projects.json`.

### Переменные `.env`

| Переменная | Обязательна | По умолчанию | Описание |
|---|---|---|---|
| `SONAR_URL` | да | — | Базовый URL SonarQube (`http://` или `https://`, допускается путь, например `https://host/sonar`) |
| `SONAR_TOKEN` | да | — | Пользовательский токен SonarQube; передаётся в заголовке `Authorization: Bearer` |
| `SONAR_VERIFY_SSL` | нет | `false` | Проверка TLS-сертификата сервера: `true` или `false` (без учёта регистра). |
| `PROJECTS_FILE` | нет | `projects.json` | Файл со списком проектов (относительный путь — рядом с `.env`) |
| `OUTPUT_FOLDER` | нет | `reports` | Папка для итоговых CSV-отчётов (относительный путь — рядом с `.env`) |
| `WORKERS` | нет | `4` | Количество параллельных воркеров |
| `HTTP_TIMEOUT_SEC` | нет | `60` | Таймаут одного HTTP-запроса, секунды |
| `EXCLUDED_BRANCHES` | нет | `p99.9,r99.9` | Зарезервированные ветки через запятую, которые не участвуют в автовыборе. |

### Файл `projects.json`

Массив объектов. Ключ `projectKey` (ключ проекта в SonarQube) обязателен; `Branch` можно оставить пустым — тогда ветка будет выбрана автоматически (см. ниже).

```json
[
  {
    "projectKey": "nsd.java:app-one",
    "Team": "Команда А",
    "Branch": "r125.1"
  },
  {
    "projectKey": "nsd.java:app-two",
    "Team": "Команда Б",
    "Branch": ""
  }
]
```

Один и тот же `projectKey` можно указать несколько раз с разными `Branch`. Поведение при ошибках в файле: дубликаты пары (`projectKey`, `Branch`) и пустые `projectKey` пропускаются с предупреждением в stderr; пустой `Team` — предупреждение; пустой `Branch` — предупреждение и автовыбор ветки.

### Выбор ветки

- **`Branch` указан** — используется как есть (в том числе зарезервированные имена и ветки любого формата). Если такой ветки в SonarQube нет — строка `Failed` с комментарием `branch '<имя>' not found in SonarQube`.
- **`Branch` пустой** — выбирается максимальная релизная ветка:
  - формат имени `^[pr]\d{2,3}\.\d$` (с учётом регистра): `p12.3`, `r123.4`;
  - ветки из `EXCLUDED_BRANCHES` пропускаются;
  - учитываются только ветки, у которых в SonarQube есть анализ; если более новая релизная ветка пропущена из-за отсутствия анализа — предупреждение в stderr;
  - ветки сравниваются по номеру как по числам (`p99.8 < p100.0`), буква не учитывается;
  - если подходящих веток нет — строка `Failed` с комментарием `no release branch found`;
  - если максимальный номер встречается и с `p`, и с `r` (например `p125.1` и `r125.1`) — строка `Failed` с комментарием `ambiguous release branch: p125.1, r125.1`.

Главная ветка проекта запрашивается без параметра `branch`, остальные — с `branch=<имя>`.

## Запуск

```bash
python main.py --env-file .env
```

Единственный аргумент командной строки — `--env-file` (по умолчанию `.env` в текущем каталоге). Все остальные параметры берутся из файла окружения.

Прогресс и подробности ошибок выводятся в stderr. Коды выхода:

| Код | Значение |
|---|---|
| `0` | Отчёт сформирован (даже если часть строк `Failed`) |
| `1` | Ошибка конфигурации, файла проектов, нет проектов, SonarQube недоступен или токен недействителен |
| `130` | Прервано пользователем (`Ctrl+C`) |

## Результат

CSV-файл в папке `OUTPUT_FOLDER` с именем `coverage_report_YYYYMMDD_N.csv` (`YYYYMMDD` — локальная дата старта запуска; `N` — порядковый номер запуска за этот день: максимальный номер среди существующих файлов за дату + 1, начиная с `1`). Кодировка UTF-8 с BOM, разделитель `;`, строки отсортированы по ключу проекта, затем по ветке. Проценты — с запятой в качестве десятичного разделителя и одним знаком после неё (округление половины вверх).

| Колонка | Источник |
|---|---|
| Ключ проекта | `projectKey` из `projects.json` |
| URL | Ссылка на дашборд: `<SONAR_URL>/dashboard?id=<ключ>&branch=<ветка>` (без `branch` для главной ветки) |
| Team | `Team` из `projects.json` |
| Ветка | Фактически использованная ветка |
| Источник ветки | `config` — из `projects.json`, `auto` — выбрана автоматически |
| Дата последнего анализа | `analysisDate` ветки, локальное время `YYYY-MM-DD HH:MM:SS` |
| New Code: определение | Режим периода New Code ветки: `PREVIOUS_VERSION`, `NUMBER_OF_DAYS=30`, `REFERENCE_BRANCH=main` и т.п. (`<режим>=<параметр>`, если параметр есть) |
| New Code: начало периода | Дата начала периода New Code, локальное время |
| Overall: Покрытие, % | `coverage` |
| Overall: Покрытие строк, % | `line_coverage` |
| Overall: Покрытие условий, % | `branch_coverage` |
| Overall: Строк к покрытию | `lines_to_cover` |
| Overall: Непокрытых строк | `uncovered_lines` |
| New Code: … (те же 5 колонок) | `new_coverage`, `new_line_coverage`, `new_branch_coverage`, `new_lines_to_cover`, `new_uncovered_lines` |
| Статус проверки | `Success` или `Failed` |
| Комментарий | Причина ошибки при `Failed` или пояснение при `Success` (см. ниже) |

| Ситуация | Статус | Метрики | Комментарий |
|---|---|---|---|
| Ошибка API: проект не найден, нет прав, сеть | `Failed` | пусто | текст ошибки |
| Ветка не найдена / не выбрана автоматически | `Failed` | пусто | см. «Выбор ветки» |
| У ветки нет ни одного анализа | `Failed` | пусто | `no analysis` |
| Анализ есть, но отчёт о покрытии не загружался | `Success` | пусто | `no coverage data` |
| Overall есть, в периоде New Code нет новых строк к покрытию | `Success` | New Code пусто | `no new lines to cover` |

## Как это работает

1. Читает `.env` и `projects.json`.
2. Запрашивает версию сервера (`/api/server/version`) и пишет её в лог; если версия не `24.12.*` — предупреждение (утилита проверялась на 24.12).
3. Проверяет токен (`/api/authentication/validate`); при ошибке — выход с кодом `1`.
4. Для каждого проекта (параллельно, `WORKERS` воркеров, общий HTTP-клиент):
   - `GET /api/project_branches/list?project=<ключ>` — список веток, дата анализа, главная ветка;
   - определяет ветку (см. «Выбор ветки»);
   - `GET /api/measures/component?component=<ключ>&branch=<ветка>&metricKeys=…&additionalFields=period` — метрики Overall и New Code и период New Code ветки.
5. Формирует имя отчёта `coverage_report_YYYYMMDD_N.csv`, создаёт папку `OUTPUT_FOLDER` при необходимости, записывает CSV и выводит сводку.

Ошибки соединения, таймауты и ответы `502`/`503`/`504` повторяются до 3 попыток (паузы 1 и 2 секунды); ответы `4xx` не повторяются.

## Диагностика

- **`HTTP 401` / `SONAR_TOKEN is invalid or expired`** — токен неверный, просрочен или отозван. Нужен пользовательский токен (`squ_…`); токен анализа проекта (`sqp_…`) не подходит для чтения метрик.
- **`HTTP 403`** — у владельца токена нет права Browse на проект.
- **`HTTP 404 … Component key '…' not found`** — неверный `projectKey`.
- **`branch '…' not found in SonarQube`** / все ветки пропали после обновления SonarQube — проверьте, что Community Branch Plugin установлен и совместим с версией сервера (версия выводится в лог при старте).
- **`[SSL: CERTIFICATE_VERIFY_FAILED]`** при `SONAR_VERIFY_SSL=true` — сертификат сервера не доверен системным хранилищем; добавьте корпоративный CA в систему или используйте `SONAR_VERIFY_SSL=false`.
